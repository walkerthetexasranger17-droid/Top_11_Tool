## Hard data rule — single screenshot only

The Player Profile may show only:

1. values directly visible/readable in the **single player screenshot used for that scan**; or
2. deterministic values derived from those visible fields using already-verified Top Eleven game data.

Do not bloat the profile with information Gemini cannot see in that screenshot.

### Allowed examples

- player name;
- age;
- displayed OVR;
- natural role(s);
- nationality/flag when visible;
- Tier when visible/selected;
- Playstyle and Playstyle level when visible/detected;
- Special Ability/Abilities when visible/detected;
- all 15 displayed attributes;
- white/key attributes derived from verified role -> key-attribute data;
- Tier bonus and reconstructed pre-Tier/base values when the Tier is known and the calculation is supported by verified data;
- player portrait/crop derived from the same screenshot.

### Not allowed unless visible in that same screenshot

Do not invent or display fields such as:

- height/weight;
- condition;
- morale;
- form;
- career stats;
- market value;
- contract expiry;
- languages;
- match history;
- biography/notes generated by AI;
- any other account/player information not visible in the scan image.

## Portrait experiment

Portrait extraction must remain independent from scanner correctness.

Preferred future experiment:

1. Existing Gemini scan performs the normal player-data task.
2. A separate optional portrait task uses the **same single screenshot** to crop/extract the player render for the collectible-style card.
3. Portrait failure must never fail player scanning/saving.
4. Fallback order: Gemini portrait -> fixed screenshot crop/mask -> neutral silhouette.
5. Test across multiple real screenshots before production release.

Do not modify the frozen scanner pipeline merely to support portrait cosmetics.
