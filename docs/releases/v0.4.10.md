# Top Eleven Tool v0.4.10 — Free-only Account Security

## v0.4.10 delta

- Removed the paid authentication card and every paid-plan prompt from the normal app.
- Authenticator-app TOTP is the supported in-app second factor.
- Added an explicit Profile & Security tooltip plus pointer/hover/focus feedback to the top-right account initial.
- Bumped the PWA cache to `te-v0-4-10`, made page navigations network-first, and added a local-launch cache-busting query so build changes appear more reliably.
- Working scanner code is byte-for-byte unchanged.

## Purpose

v0.4.10 continues the account/cloud foundation and stops treating browser-local player storage as the long-term source of truth. A signed-in Firebase account now owns the synced application data so the same squad can be used from multiple devices.

## Authentication

Implemented UI and client flows for:

- Email/password registration and sign-in.
- Google sign-in.
- Password reset email.
- Email verification.
- Display-name editing.
- Sensitive email/password changes after fresh authentication.
- TOTP authenticator enrolment and MFA sign-in resolution when Identity Platform/TOTP is enabled.

## Firestore data layer

The existing storage abstraction now writes cloud-synchronised namespaces to `/users/{uid}/kv/*` while retaining local browser copies for runtime/offline use.

Cloud-synced namespaces:

- `player:*`
- `squad:*`
- `training:normal-drills:*`
- `training:master-stock:*`
- `training:session:*`
- `teamplan:*`
- `mentor:*`

Device-local namespaces include scanner queue state and migration/schema bookkeeping. The Gemini API key was already direct-local storage and remains device-local.

On initial cloud binding, Firestore is treated as authoritative. Old local squad records are not silently uploaded to a new account.

## Security

- `firestore.rules` only allow access when `request.auth.uid == userId`.
- The app never stores Firebase server/admin secrets.
- Firebase web configuration can be supplied through the one-time setup screen; this project configuration is public identifier/config data, not a backend secret.
- Password and email changes use Firebase recent-authentication requirements.
- TOTP is optional and requires verified email plus Firebase Authentication with Identity Platform.

## Offline / multi-device behaviour

Cloud Firestore is initialised with persistent multi-tab cache support. After first successful binding, signed-in devices can use cached data offline and Firestore synchronises changes when network access returns.

## Existing application logic

The working scanner, training engines, formation/tactics logic and v0.4.6 product structure are retained. This release changes the identity/data foundation rather than rewriting the proven scanner again.

## External setup still required

The user must create a Firebase project, register a web app, enable the desired Authentication providers, create Firestore, publish the included rules, and (optionally) enable TOTP Identity Platform support. See `../setup/FIREBASE.md`.
