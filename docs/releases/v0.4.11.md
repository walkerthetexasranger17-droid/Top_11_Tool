## GitHub testing hotfix r3

Testing exposed an intermittent cloud hydration/cache race: Squad records could disappear until refresh, Player Profile could render the static shell until refresh, and some clients could still execute an older cached `app.js`. The hotfix keeps the public version at v0.4.11 and:

- requires a Firestore **server** snapshot before missing remote keys are allowed to delete local cloud-backed keys;
- treats cached live snapshots as non-authoritative for removals;
- refreshes the current cloud-backed UI after both initial sync and live updates;
- pins the runtime with internal marker `0.4.11-r3`, query-busted JS/CSS URLs and service-worker cache `te-v0-4-11-r3`.

Scanner/game-data logic is unchanged.

## GitHub testing blocker hotfix r4

The r3 mitigation did not fully solve the live test failure. r4 keeps the public version at v0.4.11 but changes the underlying state model rather than merely repainting the UI:

- the app shell stays hidden during startup until Firebase auth, cloud hydration and the requested route have completed, removing the Home-page flash on refresh;
- successful login deliberately lands on Home instead of restoring the previous Profile & Security route;
- Firestore document absence is no longer interpreted as a deletion for the same account;
- same-account local records that are missing remotely are recovered upward to Firestore instead of being erased;
- cloud deletes now write explicit tombstones so deletion is distinguishable from a stale/incomplete snapshot;
- legacy object-valued Firestore records are converted back to JSON strings before the local player layer reads them;
- non-critical training/scanner startup helpers are isolated so they cannot prevent Squad/Profile from rendering;
- internal runtime/cache marker moved to `0.4.11-r4` / `te-v0-4-11-r4`.

The scanner engine remains byte-for-byte unchanged.


## GitHub testing blocker hotfix r5

r4 still allowed Firestore's persistent browser cache to compete with the app's own localStorage mirror. That created a second offline state layer and could replay stale cached snapshots while the user navigated between Squad and Player Profile. r5 keeps the public version at v0.4.11 and simplifies the data path:

- removes Firestore persistent IndexedDB caching; Firestore now uses only its in-memory cache;
- localStorage is the single immediate runtime/offline working copy;
- initial hydration reads from the Firestore server only, with local data preserved if the server is unavailable;
- live listeners ignore `fromCache` and `hasPendingWrites` snapshots, so cached/pending Firestore state cannot overwrite the UI working copy;
- app writes update localStorage immediately and are queued to Firestore in a durable per-user outbox instead of blocking the UI on network round-trips;
- pending local edits/deletes win over incoming server snapshots until the outbox has been confirmed;
- cloud deletes remain explicit tombstones, so document absence is never confused with deletion;
- account switching clears only the previous account's synced working copy before server hydration;
- internal runtime/cache marker moved to `0.4.11-r5` / `te-v0-4-11-r5`.

Scanner/game-data logic remains unchanged.
