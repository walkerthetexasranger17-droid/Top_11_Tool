Scanner reconciliation fix
- Root cause in Beta 1: scanner-engine.js already calculated aggregate and OVR discrepancy checks, but app.js only displayed those checks. validateScanForm() validated ordinary ranges/roles and did not reject failed scanner checks, so state.scan.skills could still be saved even when the app already knew the scan was inconsistent.
- Beta 2 adds a targeted OVR re-read using alternate threshold passes of the existing local digit recogniser.
- Reconciliation may switch OVR only to a value that the recogniser actually returned as a candidate and only when it resolves the OVR/attribute-average mismatch.
- If no recognised candidate resolves the mismatch, the original value is retained and the scan remains unresolved rather than being forced to match.
- Scanner review now continuously recalculates Defence/Attack/Physical (or Goalkeeping/Physical) aggregate checks plus OVR when the user edits OVR or a parsed skill.
- Save Player is disabled while any numerical verification check remains unresolved.
- Parsed attribute values can be corrected manually from the visible screenshot; Save unlocks only after reconciliation passes.
- Saved scanner metadata now records the final checks and resolved/unresolved validation state.
